# Command: /deep-bagu

## 用途

调用 `.codebuddy/skills/deep-bagu/SKILL.md`，对用户提出的技术问题按 L1/L2/L3 深度档位输出可核对、可落地的技术方案或故障复盘。

## 触发方式

满足任一条件即触发：

1. 用户显式输入：`/deep-bagu <问题>`
2. 用户消息包含：八股、Interview、JVM、GC、并发、AQS、MySQL、Redis、Spring、分布式、底层原理、源码、调优、排查 等关键词
3. 用户明显在问经典技术知识点，但希望从工程实践角度理解

## 执行步骤

1. 读取 `.codebuddy/skills/deep-bagu/SKILL.md`，按其规则执行，不要凭记忆套模板。
2. 识别问题所属主题：JVM/GC、并发/AQS/JMM、MySQL、Redis、Spring、分布式、通用。
3. 判定深度档位：
   - 普通概念、单点参数 → L1（≤40 行）
   - 机制说明、常见故障、参数调优 → L2（≤120 行）
   - 线上故障复盘、复杂性能问题、源码级诉求 → L3（≤250 行）
   - 用户未说明且问题宽泛时，先收敛范围再定档，不要默认 L3。
4. 按档位组织输出：
   - L1：一句话本质 + 关键机制 + 1 个可核对验证方式 + 1 个坑
   - L2/L3：使用 SKILL.md 第 5 节模板 `0. 结论与适用范围` 到 `7. 生产落地建议`，标题不改写、不增减
5. 按主题证据矩阵取证据，每个主题至少 2 类可核对证据；需要具体命令时读 `references/tooling.md` 对应小节。
6. 按质量闸门自检后输出：版本标注、证据可复现、危险命令风险提示、无伪造细节、长度符合档位。
7. 表述按 SKILL.md 第 8 节替换表自查：不出现求职、考核、背诵类字眼，标题与正文一视同仁。

## 输出约束（强制）

- 不伪造日志样例、源码行号、默认值、压测数据、事故案例；不确定处写"需按版本确认"。
- 危险命令必须同时给风险提示与低峰期/审批/脱敏/回滚条件。
- 不展示真实连接串、密码、用户数据、内部域名。
- 不使用"第一点、第二点、这样回答"式口播行文，整体写成技术方案或故障复盘。
- 简单问题不写长文；不得为了显得深入而堆砌源码、内核、字节码内容。

## 使用示例

### 示例 1（L1）

```text
/deep-bagu 解释一下什么是 TLAB
```

预期：≤40 行，一句话本质 + 分配机制 + 一个验证方式 + 一个坑，不展开 GC 全流程。

### 示例 2（L2）

```text
/deep-bagu JVM 运行时内存区域有哪些，各对应什么错误
```

预期：≤120 行，模板完整，每类区域对应错误、参数与采集命令。

### 示例 3（L3）

```text
/deep-bagu 线上服务频繁 Full GC 后 OOM，帮我做故障复盘
```

预期：≤250 行，含 GC 字段、采集顺序、dump 风险提示、调优基线、灰度与回滚条件。
