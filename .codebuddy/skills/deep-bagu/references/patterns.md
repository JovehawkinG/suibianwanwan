# 故障模式、误判与反例

## 1. 常见误判

| 现象 | 容易误判为 | 更可能的根因 | 验证方式 |
|---|---|---|---|
| 接口周期性变慢 | CPU 不足 | GC 停顿、 safepoint、锁竞争 | GC 日志、`jstat`、线程栈 |
| 连接池耗尽 | 慢 SQL | 连接泄漏、事务过长、下游阻塞 | 连接池指标、线程栈、慢日志 |
| Redis 集群抖动 | 集群容量不足 | 热 key、大 key、慢查询、网络 | `INFO`、`slowlog`、key 采样 |
| 线程池队列堆积 | 下游接口慢 | 核心线程不足、队列无界、拒绝策略不当 | 线程池指标、任务耗时、线程栈 |
| 元空间增长 | 堆内存泄漏 | 动态类生成、代理膨胀、类加载器泄漏 | `jcmd GC.heap_info`、类加载统计、MAT |
| Redis 内存上涨 | 数据量增长 | 内存碎片、过期策略、复制缓冲区 | `INFO memory`、碎片率、过期键统计 |
| MySQL 偶发超时 | 慢查询 | 锁等待、间隙锁、事务隔离级别 | `innodb status`、锁等待表、执行计划 |
| 重试后雪崩 | 容量不足 | 重试风暴、超时设置不合理、缺少熔断 | 重试指标、链路追踪、压测 |

## 2. 常见故障模式

- OOM：堆、元空间、直接内存、native thread 四类分开排查。
- 长停顿：GC、safepoint、锁、磁盘、网络分别验证。
- 死锁：线程死锁、数据库锁等待、分布式锁续期失败。
- 连接泄漏：连接池、HTTP 客户端、数据库事务、流未关闭。
- 缓存问题：击穿、穿透、雪崩、热 key、大 key。
- 重试风暴：超时叠加重试、无退避、无幂等、无熔断。
- 消息积压：消费能力不足、重投、死信、分区倾斜。
- 分布式锁失效：续期失败、时钟漂移、锁误删、租约过期。

## 3. 反例

### 反例 1：只列概念

问题：只写“堆、栈、方法区、程序计数器”，没有错误类型、参数、工具、故障场景。  
修正：至少给每类内存区域对应错误、参数、采集命令、一个生产坑。

### 反例 2：默认值无版本

问题：写“默认值是 X”，未注明 JDK / MySQL / Redis / Spring 版本。  
修正：标注版本；不确定时写“需按版本确认”。

### 反例 3：伪造日志与行号

问题：编造具体日志、源码行号、压测数据。  
修正：日志标明“示例结构”；源码只给关键类/方法/机制路径；压测数据注明环境与来源。

### 反例 4：危险命令无提示

问题：直接让生产执行堆 dump、`KEYS *`、全表扫描、详细追踪。  
修正：给风险、低峰期、审批、限时、脱敏、回滚条件。

### 反例 5：无回滚方案

问题：只给调优参数，不给基线、灰度、观察指标、回滚条件。  
修正：参数调优必须附变更方案与回滚条件。

## 4. 排查链路模板

1. 明确现象：错误码、耗时、影响面、开始时间、变更记录。
2. 分层定位：入口 → 应用 → 线程/锁 → 中间件 → 存储 → 网络。
3. 最小证据：指标、日志、线程栈、慢日志、链路追踪。
4. 根因验证：反证、对照、灰度、回放、压测。
5. 修复与预防：参数、代码、容量、监控、告警、预案。
6. 复盘：时间线、根因、影响、改进项、责任人、截止时间。
