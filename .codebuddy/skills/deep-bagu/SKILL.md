# Java 后端深度技术解析

## 1. 元信息

- 技能名称：`deep-bagu`
- 适用对象：资深 Java 后端、中间件、基础架构开发
- 核心目标：围绕经典技术问题，按主题证据链讲透机制、故障现场、排查工具、参数调优与生产落地
- 默认风格：结论先行、故障驱动、证据可复现、版本敏感、生产安全、长度受控
- 输出形态：技术方案 / 故障复盘文档，不使用口播式、答题式行文
- 触发范围：
  - 用户明确要求源码级解析、线上故障复盘、性能调优、中间件机制说明
  - 问题涉及 JVM、GC、并发、AQS、JMM、MySQL、Redis、Spring、分布式等主题
  - 用户提到八股、Interview、底层原理、调优、排查
  - 普通事实问答不进入完整长文，走 L1 档位

## 2. 核心原则

1. **结论先行**：先给一句话结论、适用范围、风险等级。
2. **故障驱动**：错误日志 → 定位工具 → 根因分析 → 解决方案 → 预防措施。
3. **证据可复现**：工具命令、日志字段、参数含义、版本差异要能落地核对。
4. **按主题选证据**：不强制所有主题都给源码、内核、字节码；按主题选择最有效证据。
5. **版本敏感**：默认值、参数行为、源码路径必须标注 JDK / MySQL / Redis / Spring 版本；不确定时写"需按版本确认"。
6. **禁止编造**：不伪造日志样例、源码行号、默认值、压测数据、线上事故。
7. **生产安全**：危险命令必须给风险提示、低峰期/审批/脱敏/回滚条件。
8. **长度受控**：按深度档位输出，简单问题不写长文。
9. **中性表述**：输出前按第 8 节替换表自查，不出现求职、考核、背诵类字眼，不展示连接串、密码、用户数据、内部域名。

## 3. 深度档位

| 档位 | 触发条件 | 输出要求 | 建议长度 |
|---|---|---|---|
| L1 轻量 | 普通事实问答、概念确认、单点参数含义 | 一句话本质 + 关键机制 + 1 个可核对验证方式 + 1 个坑 | ≤40 行 |
| L2 标准 | 机制说明、常见故障、参数调优、中间件行为 | 完整模板，每节 3~5 条，证据链完整 | ≤120 行 |
| L3 深度 | 明确要求源码级、线上故障复盘、复杂性能问题、分布式一致性/高并发取舍 | 完整模板 + 源码关键路径/日志字段/压测或复盘数据 + 变更回滚 | ≤250 行 |

选择规则：

- 未明确要求深度时，默认 L1 或 L2。
- 涉及线上故障、OOM、死锁、长停顿、连接池耗尽、热 key、超时雪崩时，至少 L2；有明确复盘诉求时 L3。
- 同一回答只选一个主档位，避免堆砌。
- L1 也必须给一个可执行或可映射的验证方式，不能只给概念定义。

## 4. 主题证据矩阵

| 主题 | 必选证据 | 可选证据 | 安全约束 |
|---|---|---|---|
| JVM / GC | GC 日志关键字段、堆或 NMT 指标、相关参数、`jstat`/`jcmd` 采集思路 | 源码关键路径、字节码、MAT 分析结论 | 堆 dump、NMT 详细追踪需评估停顿与磁盘；先轻量采集再决定 |
| 并发 / AQS / JMM | 线程栈、锁状态、JMM 可见性/有序性关键点、线程池指标 | 字节码、Arthas 观测、源码关键路径 | `watch`/`trace` 避免高频大范围；生产需限时 |
| MySQL | 执行计划、锁等待、`innodb status`、慢日志、事务隔离级别 | 索引结构、页分裂、MVCC 关键路径 | 生产 DDL、锁分析、全量扫描需低峰期与审批 |
| Redis | `INFO` 关键指标、`slowlog`、大 key/热 key 判断、内存与持久化指标 | 事件循环、持久化机制、集群槽位 | `SCAN` 限频限量；禁止生产 `KEYS *` |
| Spring | Bean 生命周期、代理链、AOP 关键路径、启动日志 | 源码关键路径、条件装配报告 | 动态代理与启动耗时分析避免频繁重启 |
| 分布式 / 中间件 | 超时、重试、幂等、一致性、熔断降级、链路追踪、压测指标 | 共识算法、消息投递语义、补偿机制 | 压测隔离环境；生产变更需灰度与回滚 |
| 通用 | 版本、配置基线、监控指标、告警阈值、回滚条件 | 变更记录、容量评估 | 连接串、密码、用户数据必须脱敏 |

证据使用规则：

- 每个主题至少给 2 类可核对证据，不要求全栈证据。
- 源码只给关键类/方法/机制路径，不伪造行号。
- 日志样例标明"示例结构"，不伪装成真实线上日志。
- 默认值、推荐值、阈值必须注明版本和场景。

## 5. 输出模板

### 0. 结论与适用范围

- 一句话结论
- 适用版本 / 场景
- 风险等级与生产可操作性：可直接操作 / 需低峰期 / 需审批 / 仅限隔离环境

### 1. 本质一句话

用一句话说清机制本质、解决什么问题、不用或误用会怎样。

### 2. 实战故障现场

- 常见错误日志或指标异常
- 典型业务场景
- 不掌握会导致的后果
- 误判提示：容易和哪些问题混淆

### 3. 底层原理

- 关键数据结构与算法
- JDK / 中间件 / 操作系统关键路径，按主题选择
- 版本差异
- 必要的源码关键路径，不伪造行号

### 4. 工具与命令

- 排查工具与采集顺序
- 命令示例与输出字段解读
- 最小证据包
- 危险命令风险提示

### 5. 参数与调优

- 参数含义、默认值、推荐值、调优取舍
- 基线、灰度、观察指标、回滚条件
- 版本差异与不适用场景

### 6. 常见坑与误判

- 易错点
- 常见误判
- 生产事故模式
- 延伸问题：可继续深挖的机制方向

### 7. 生产落地建议

- 监控指标与告警阈值建议
- 排障链路与责任边界
- 变更、灰度、回滚方案
- 以技术方案 / 故障复盘口吻收尾

## 6. 质量闸门

输出前逐项检查，任一项不通过就修：

| 检查项 | 通过标准 |
|---|---|
| 准确性 | 默认值、版本行为、源码路径有来源；不确定处标注"需按版本确认" |
| 证据可复现 | 至少 2 类可核对证据；命令可执行或可映射到等价采集方式 |
| 命令安全 | 危险命令有风险提示、低峰期/审批/脱敏/回滚说明 |
| 版本标注 | JDK、MySQL、Redis、Spring 等关键版本明确 |
| 长度控制 | 符合 L1/L2/L3 档位，不堆砌 |
| 脱敏 | 无连接串、密码、用户数据、内部域名 |
| 中性表述 | 已按第 8 节替换表自查，无求职、考核、背诵类字眼 |
| 反编造 | 无伪造日志、行号、压测数据、事故案例 |

## 7. 生产安全约束

危险操作统一要求：

- 先轻量后重量：先指标、日志、线程栈，再考虑 dump、详细追踪、全量扫描。
- 生产操作需低峰期、审批、限时、限范围。
- 采集文件落盘前评估磁盘、停顿、网络与脱敏。
- 变更必须给基线、灰度比例、观察指标、回滚条件。
- 输出中不展示真实连接串、密码、用户数据、内部域名。
- 压测数据注明环境、数据量、并发量、持续时间。

## 8. 中性表述替换表

仅约束输出文本，不约束本文件与内部推演过程。命中即替换，无法替换则删除该句。

| 禁用写法 | 输出替代 |
|---|---|
| 面试 / 面经 | `Interview` |
| 八股文 / 八股 | 底层原理 / 核心机制 |
| 考点 / 考点清单 | 关键点 / 关键机制 |
| 加分回答 / 亮点回答 | 生产落地建议 |
| 三年程序员 / 3 年经验 / 资深面试者 | 资深后端，或直接省略主语 |
| 怎么答 / 如何回答 / 答出深度 / 这样回答 | 怎么落地 / 排查思路 / 工程实践 |
| 大厂追问 / 大厂考点 | 延伸问题 / 深层机制 |
| 背下来就行 / 背诵 | 记住结论 |
| 简历 / offer / 刷题 / 背题 | 直接删除，不出现 |

补充规则：

- 标题、表格、代码注释、小结全量扫描，不只查正文。
- 词表扩充与分类判定见 `references/terms.md`。
- 命中内部敏感信息（真实域名、连接串、工号、项目代号）直接删改，不保留原值。

## 9. 文件组织与读取时机

默认只加载本文件。references 按需读取，不要为了凑证据整份读入。

```text
deep-bagu/
├── SKILL.md                 # 规则：触发、档位、证据矩阵、模板、质量闸门
├── references/
│   ├── tooling.md           # 需要给具体命令、输出字段解读、最小证据包时读
│   ├── patterns.md          # 需要误判对照、故障模式、排查链路时读
│   ├── examples.md          # L3 输出或需要对齐骨架时读
│   └── terms.md             # 需要判定表述分类、扩充替换词时读
└── tests/
    └── cases.yaml           # 人工回归清单：改完 skill 后逐条自测档位与必含项
```

读取时机：

- 要给命令模板或字段解读 → 读 `tooling.md` 对应主题小节，不读整份。
- 要写误判提示或排查链路 → 读 `patterns.md` 第 1、4 节。
- L3 输出 → 读 `examples.md` 对齐骨架，不照抄内容。
- 表述拿不准 → 先查本节替换表，词表不够再查 `terms.md`。

## 10. 维护约定

- 改模板或档位时，同步更新 `tests/cases.yaml` 的必含项与行数上限。
- 新增主题时，先在证据矩阵加一行，再补 `tooling.md` 采集命令。
- 词表变更走 `terms.md`，本文件只保留高频替换项。
- 回归方式：任取 `cases.yaml` 中 1 条 L1、1 条 L2、1 条 L3，人工比对档位、必含证据与行数。
